# ORI-08 — автономная регрессионная и браузерная приёмка

**Дата:** 2026-11-06. **Ветка:** `feature/humanoid-clothing-rework`
(после rebase на `dev`). **Статус:** основная проверка завершена,
физика Ragdoll требует дополнительной стабилизации.

## Среда и границы

- Отдельный headless Chrome 157 с изолированными browser contexts и
  программным/ограниченным WebGL; адрес тестовой игры
  `http://127.0.0.1:18881/index_debug.html`.
- Собственный WebSocket-мир Python на `127.0.0.1:18882` со
  **временным файлом мира** в `/tmp/fc-ori08-*/world.json`. Публичный
  сервер и пользовательские сохранения не менялись.
- Выбор персонажа/слот в каждом изолированном browser context.
- Проверки проводились через настоящий DOM, canvas, игровой
  `window.__gameDebug`, Chrome DevTools Protocol, touch events и
  независимый настоящий WebSocket-клиент.
- Изолированный рендер на программном/виртуализованном WebGL давал
  необычно низкий FPS. **Не использовать эти FPS как оценку
  производительности на физической GPU или телефоне.**

## Исправление и регрессионная защита

После унификации всех персонажей до 53 костей остались две ссылки на
удалённый флаг `humanoid` в `createRagdoll()`. При первом падении в
браузере возникал `ReferenceError`. Убран устаревший выбор демпфирования
и одинаково включён settling для всех игровых ригов (кроме сна на
кровати). Обновлён query-version импортов HTML → menu → main → ragdoll,
чтобы Chrome не продолжал использовать старый ESM из cache.

Тест `tests/debug-ragdoll.test.mjs` не даёт случайно вернуть удалённый
флаг. Режимы legacy и male проверены в действующем браузере. Сама
переменная более не используется в этом модуле.

## Открытый дефект (не скрывать при завершении этапа)

При некоторых длительных падениях legacy возникает
`RuntimeError: unreachable` внутри
`@dimforge/rapier3d-compat@0.20.0`, цепочка вызовов:
`stepRagdollPhysics → world.step → WASM`.
Не подтверждено, является ли причиной WebGL/headless environment,
контактная конфигурация или логика settling. Простой замены демпфирования
без отдельного теста на устойчивость **недостаточно**. Игра уже умеет
поймать исключение, отключить физическую позу и восстановить управление;
новая активация в той же сессии блокируется до reload.

### Для окончательной визуальной приёмки

Повторить на GPU/настоящем телефоне: два человеческих клиента с разными
моделями, повороты головы при движении и ударе, низкие цели, рубка обоими
топорами, ragdoll legacy после 10–30 секунд и подъём, смерть/respawn,
сравнить foot sliding и частоту кадров. Если WASM продолжает падать,
создать отдельный регрессионный тест с реальным Rapier World и проверить
физические joint limits/collisions. Не закрывать этот дефект на основе
одних только unit-тестов.
