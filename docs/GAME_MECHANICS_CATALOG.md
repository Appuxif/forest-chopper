## 5. Баланс и ограничения, важные при изменениях

- **Дистанция подбора:** лесные предметы не дальше 2.4 м; коробки — 2.8 м
  (`forest-resources.js`, `ground-boxes.js`, `pickup-interaction.js`).
- **Экранная зона прицела:** `PICKUP_RETICLE_RADIUS = 0.28` в NDC;
  визуальное выделение только для цели в пределах зоны. Touch-кнопка
  допускает ближайшую достижимую цель без точного наведения.
- **Респавн ресурсов:** `RESOURCE_RESPAWN_SECONDS=600`.
- **Инвентарь:** `BASE_BAG_SLOTS=12`, `QUICK_SLOTS=4`; рецепты
  определены в `inventory.js`, не дублировать их в другом модуле.
- **Стамина:** `MAX_VITALS=5`, `STAMINA_HIT_COST=1`,
  `STAMINA_JUMP_COST=1`; точная проверка ресурса действия в `vitals.js`.
- **Коробки:** TTL=3600 с; при переполнении сумки подбор отклоняется.
- **Один общий мир в online:** успешность действий определяет Python-сервер;
  клиентский reticle или preview лишь визуальная подсказка.
- **MSAA:** Ultra/High включено, Medium/Low выключено; FPS зависит от
  GPU/кадра, реальные замеры не заменяются тестами.

## 6. Контракты и тесты по изменениям

| Если меняете | Убедитесь в следующем |
| --- | --- |
| Seed/генерацию деревьев | Стабильность ID, совпадение мира у JS/Python, старые сохранения |
| Ландшафт/воду | Совпадение высот/коллизий на сервере, границы чанков |
| Ресурсы | Нельзя подобрать удалённый, скрытый/неразрешённый предмет, нельзя обойти cooldown |
| Инвентарь/крафт | Сервер и клиент используют те же ограничения и рецепты |
| Сетевое событие | Взаимная поддержка в `multiplayer.js` и `forest_server.py`; тесты сообщений |
| Новую UI-механику | ПК + touch, отсутствие наложений, описание управления |
| Графический preset | Не изменять игровой seed и gameplay; проверить производительность |
| Save | Проверка старого формата, не перезаписывать offline при multiplayer |
| Анимации/GLB | Совместимость текущего `src/animations.js` с игровым rig |
| Стриминг | Отмена устаревших задач и отсутствие пропаданий при движении/смене seed |

Тесты из корня проекта:

```bash
node --test tests/*.test.mjs
python3 -m unittest discover -s tests -v
```

**Как поддерживать каталог:** при добавлении/изменении механики обновляйте
соответствующий ID, её ограничения, ссылки на код и тесты **в том же коммите**.
Новые идеи помещайте в [GAME_DESIGN.md](GAME_DESIGN.md) как предложения,
а не маркируйте здесь как LIVE до фактической реализации.

## 7. Известные расхождения интерфейсов, требующие проверки

- **Общий подбор выпавших коробок:** `pickupCandidates()` читает
  `ctx.groundBoxes?.boxes`, но `createGroundBoxes()` сейчас не предоставляет
  `boxes` в возвращаемом API; прицел и общая клавиша подбора могут
  пропускать коробки. Это зафиксированное при сверке **несоответствие кода**,
  а не доказанное браузерным тестом поведение; исправление относится к
  отдельной игровой задаче, вне документационного обновления.
